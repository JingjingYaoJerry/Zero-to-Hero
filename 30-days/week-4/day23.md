## 📋 今日概览

机器学习工程师面试不只考"你读过什么论文"，还考"你能把论文实现出来吗"和"你知道工程上的坑吗"。  
今天的目标：**重新审视你学过的论文，补全工程视角**

## ⏱️ 最小启动版本（15 分钟）

**用 AI 补全 2 篇论文的工程视角：**

选你最熟悉的 2 篇论文（推荐：Transformer + 你方向的一篇），问：

```
从机器学习工程师的工程实现角度，帮我分析 [论文名]：
1. 输入输出的格式是什么
2. 实现时最容易出错的 3 个地方
3. 模型训练时的常见 bug 和 debug 方法
4. 推理时的性能瓶颈在哪里
5. 如果要上生产环境，需要考虑哪些额外问题
6. 面试官可能问的工程类问题（不是原理，而是实现）
```

把答案更新到对应论文卡的"工程视角"部分。

## 🚀 完整版任务（40 分钟）

### 步骤 1：工程视角速读（20 分钟）

对 3-4 篇论文，完成上方提示词的分析。

优先级：
1. Transformer（几乎所有方向都要用）
2. 你方向的核心论文
3. BatchNorm / Dropout（训练技巧，工程必考）

### 步骤 2：总结"工程踩坑清单"（10 分钟）

```
请帮我总结机器学习工程师在以下场景中最常见的 5 个踩坑点：

场景 1：从零训练一个 Transformer 模型
场景 2：微调一个预训练模型（如 BERT）
场景 3：使用 XGBoost/随机森林处理结构化数据
场景 4：将模型从实验部署到生产环境

每个场景列出：踩坑点 + 原因 + 如何避免
```

### 步骤 3：练习"工程问题"回答（10 分钟）

面试官很喜欢问这类题，练习回答：

**题 1：** "如果你的模型在 train 上过拟合，你会怎么处理？"

**题 2：** "你的模型推理速度很慢，有哪些优化手段？"

**题 3：** "在 PyTorch 中，model.eval() 做了什么？为什么推理时一定要调用它？"

```
我的回答：[你的答案]
请帮我评估并补全。
```
